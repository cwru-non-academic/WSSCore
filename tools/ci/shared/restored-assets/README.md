# Restored package assets

Canonical owner: WSSCore tools/ArtifactBuild/RestoredPackageAssets.cs. Core ArtifactBuild and the CSharp/Python output validator use this same implementation. Consumer copies are whole-file managed sources in tools/ci/sync-tooling.json, never independently maintained.

The original package metadata resolution was extracted from ArtifactBuild. Every affected trusted SDK restore/build/publish/build-capable test invocation must pass -p:DisablePackageAssetsCache=true. Default SDK ResolvePackageAssets can retain a previously selected fallback in its binary cache even after a primary package appears; this helper intentionally does not parse that cache. A restore alone does not invalidate that cached selection. Proof-bearing builds restore first, capture, then build without restore under the uncached contract and verify against the same proof. Version 2 corrects its inherited first-existing-asset fallback: select the first declared package folder containing the exact package/version extraction marker (.nupkg.metadata or the legacy package .nupkg.sha512), then require the declared asset inside that one package directory. An incomplete directory without either marker is not selected. A selected package with a missing asset fails; another cache cannot supply that asset. PackageRootSelection.Tests.ps1 compares these cases against actual SDK 9.0.316 ResolvePackageAssets with package-asset caching disabled. Marker contents are not a package-authentication claim.

CaptureProjectAsset creates an immutable in-process proof of the exact project path and SHA256, assets path and SHA256, package identity, selected package directory, neutral asset path and SHA256. Callers capture before selectable code. AssertProjectAssetProof rechecks metadata, selection identity and bytes afterward. The verifier uses the original captured neutral hash in its allowlist, so newly introduced roots or modified files cannot redefine acceptable output. The bridge loads only its trusted sibling C# source. A proof is never read from child-written JSON.

Project validation requires the caller's exact project, restored net9.0 graph and exact System.IO.Ports/8.0.0 package/type. The neutral lib/net8.0 asset must be declared by that package. This is an explicit output-policy alternative to the verified host runtime DLL, not a claim that every RID graph copies the neutral DLL. RID runtime target entries may differ. Unrelated project/framework/package graphs fail. Root output Ports remains optional, but restore-input validation is unconditional.

CSharp selected/baseline/hosted and Python platform callers retain this parent proof across selectable children. CSharp repeated stages execute the captured compiled assembly through the installed SDK VSTest console, with copy-local adapters/dependencies and output inventory checks, without reevaluating MSBuild imports. Python completes the trusted fixture baseline and native/TRX gates before selected smoke, snapshots that evidence, and performs no later project evaluation. These integrity checks do not sandbox selected code or protect against an arbitrary concurrent operating-system adversary. Product/fixture pins, payload checks, macOS pair/capability checks, obsolete-dependency checks, runtime/native proof and source-selection gates remain separate authorities.

RestoredAssets.Tests.ps1 uses fabricated bytes only. RestoreLayout.Tests.ps1 uses a local fabricated NuGet package, configured cache/fallback roots, spaces and artifacts-path. Neither fixture executes package assemblies or WSS native code. Full hosted/native acceptance remains distinct.
Core prebuilt staging (`build-all --no-build` and `stage`) remains an explicit package projection, not an attestation of historical SDK cache/build provenance. Manifest package overrides are read from current exact restore metadata, checked against the compile asset and emitted reference for managed files, copied from that approved source, and hash-checked. Arbitrary prebuilt Ports bytes are not used as the override authority. Existing restored closure, assembly, native payload and manifest checks remain mandatory; no-build does not prove the earlier compiler used uncached resolution. PrebuiltPackageOverride.Tests.ps1 exercises the real build-time staging method with inert native-shaped bytes: foreign prebuilt bytes are ignored and a missing selected source fails without fallback.

CachedPackageResolution.Tests.ps1 retains the real default SDK cached-fallback reproduction and the paired cache-disabled invocation. It captures before the corrected SDK resolution, then verifies that captured source and rejects cached-fallback/foreign output. This test never loads the fabricated package DLL.
